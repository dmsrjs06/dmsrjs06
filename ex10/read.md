# 과제 10: 정렬 알고리즘의 성능 및 안정성 비교

선택 정렬 · 버블 정렬(일반 / 조기 종료) · 삽입 정렬(`>` / `>=`)을 직접 구현하고,
첫 번째 키(Key 1) 기준으로 **비교 횟수 · 데이터 이동 횟수 · 안정성**을 측정·분석했습니다.

- 소스: `sort_compare.c` / 전체 실행 로그: `result.txt`
- 빌드·실행: `gcc -O2 -o sort_compare sort_compare.c && ./sort_compare`
- 난수 시드를 고정(`srand(20240601)`)했으므로 같은 환경에서 같은 결과가 재현됩니다.

---

## 1. 구현 및 측정 방법

| 항목 | 내용 |
|---|---|
| 데이터 | `struct {key1, key2, id}` — key1·key2는 0~1,000,000 난수, `id`는 원래 입력 순서(정렬 기준 아님, 안정성 검증용) |
| 비교 횟수 | 정렬 순서를 결정하기 위한 **key1 비교**만 1회로 계산 (반복문 인덱스 비교 제외) |
| 이동 횟수 | 데이터 전체를 temp/배열에 복사·대입할 때마다 1회 (교환 = 3회) |
| 선택 정렬 | 최솟값 위치 `m`을 찾은 뒤 `m != i`일 때만 교환 (이동 3회) |
| 버블 정렬 | `j < n-1-i` 범위로 `n-1` 패스. 조기 종료판은 한 패스에서 교환이 없으면 종료 |
| 삽입 정렬 | `cur = a[i]`(1회) → 조건 만족 동안 한 칸씩 이동(각 1회) → 최종 위치 대입(1회) |
| 검증 | 매 실행마다 ① key1 오름차순 여부 ② 원본의 순열인지(데이터 유실·복제 없음, key1/key2/id 일치) 확인 |
| 공정성 | 매 반복에서 난수 데이터 1개를 만들고 **동일한 복사본**을 모든 알고리즘에 제공. 사전 정렬·복사·데이터 생성은 카운트에서 제외 |

## 2. 무작위 데이터 100회 실험 (N = 10,000)

| 알고리즘 | 총 비교 횟수 | 평균 비교 횟수 | 평균 이동 횟수 |
|---|---:|---:|---:|
| 선택 정렬 | 4,999,500,000 | 49,995,000.00 | 29,971.08 |
| 버블 정렬 (일반) | 4,999,500,000 | 49,995,000.00 | 75,066,398.64 |
| 버블 정렬 (조기 종료) | 4,998,467,502 | 49,984,675.02 | 75,066,398.64 |
| 삽입 정렬 (`>`) | 2,503,212,319 | 25,032,123.19 | 25,042,130.88 |
| (참고) 삽입 정렬 (`>=`) | 2,503,217,224 | 25,032,172.24 | 25,042,179.93 |

**100회 모두 정렬 결과가 올바름(오름차순 + 순열 보존)을 확인했습니다.**

### 해석
- **선택 정렬**: 비교는 입력과 무관하게 항상 `n(n-1)/2 = 49,995,000`회입니다. 100회 총합이 정확히 이 값의 100배(4,999,500,000)로 나왔습니다. 이동은 위치당 최대 1회 교환(3회)이라 평균 약 3만 회로, 세 알고리즘 중 **이동이 압도적으로 적습니다.**
- **일반 버블 정렬**: 비교는 선택 정렬과 똑같이 49,995,000회입니다. 이동은 평균 약 7,507만 회인데, 이는 버블 정렬의 교환 횟수가 **역전(inversion) 쌍의 수**와 같고 교환 1회 = 이동 3회이기 때문입니다. 무작위 배열의 평균 역전 수는 `n(n-1)/4 ≈ 2,500만`이므로 3배인 약 7,500만이 나옵니다. 가장 이동이 많은 알고리즘입니다.
- **삽입 정렬**: 비교·이동 모두 역전 수에 비례합니다. 평균 비교 약 2,503만 회로 **선택·버블의 약 절반**입니다(앞쪽 정렬 구간에서 평균 절반만 훑고 멈추므로). 이동은 `역전 수 + 2(n-1)`(임시 저장 + 최종 대입)이며, 실측 25,042,130.88 − 19,998 ≈ 25,022,133이 이론 평균 역전 수 2,499만과 거의 일치합니다.

## 3. 버블 정렬 조기 종료의 효과

| 입력 | 일반 버블 비교 | 조기 종료 버블 비교 | 감소율 |
|---|---:|---:|---:|
| 무작위 (평균) | 49,995,000 | 49,984,675 | 약 0.02% |
| 정렬됨 | 49,995,000 | **9,999** | 약 99.98% |
| 역순 | 49,995,000 | 49,995,000 | 0% |
| 일부 정렬 | 49,995,000 | 49,411,260 | 약 1.2% |

- **무작위**: 조기 종료가 거의 도움이 되지 않았습니다. 무작위 배열에서는 맨 끝 근처의 몇 패스를 제외하면 거의 모든 패스에서 교환이 발생해, 평균 약 1만 번(1패스 분량) 절약에 그쳤습니다.
- **이미 정렬됨**: 첫 패스(비교 9,999회)에서 교환이 없으므로 즉시 종료합니다. `O(n²) → O(n)`.
- **역순**: 모든 패스에서 교환이 발생하므로 종료 조건이 한 번도 작동하지 않아 일반 버블과 같습니다.
- **조기 종료는 비교 횟수만 줄이고, 이동 횟수는 두 방식이 항상 동일**합니다(교환 횟수는 역전 수로 고정되기 때문입니다. 실측에서도 모든 입력에서 이동이 같았습니다).

## 4. 안정성 검증

### 4.1 검증 방법
각 데이터에 원래 입력 순서 `id`를 부여하고, 정렬 후 **key1이 같은 인접 데이터 쌍에서 `id`가 증가하는지**(원래 순서 유지)를 검사해 위반 횟수를 셌습니다. 위반이 0이면 안정, 1 이상이면 불안정입니다.

### 4.2 사용한 입력 데이터
1. **과제 예시 4개 데이터**: `(527,100) (527,200) (125,300) (892,400)`
2. **중복이 많은 시험 데이터**: 2,000개, key1을 0~99에서 생성(값당 평균 약 20개 중복), key2는 난수
3. **무작위 10,000개**: 정렬 후 key1이 같은 인접 쌍이 **53쌍** 자연 발생(범위 100만에서도 중복이 존재)

무작위 데이터만으로는 중복이 적어 검증이 약하므로 2번 데이터를 별도로 만들었습니다.

### 4.3 결과

**(1) 예시 데이터 정렬 결과** (key1 = 527인 두 데이터의 순서에 주목)

| 알고리즘 | 결과 | 527 데이터 순서 |
|---|---|---|
| 선택 정렬 | (125,300) **(527,200) (527,100)** (892,400) | 뒤바뀜 → 불안정 |
| 버블 정렬 | (125,300) (527,100) (527,200) (892,400) | 유지 → 안정 |
| 삽입 정렬 `>` | (125,300) (527,100) (527,200) (892,400) | 유지 → 안정 |
| 삽입 정렬 `>=` | (125,300) **(527,200) (527,100)** (892,400) | 뒤바뀜 → 불안정 |

**(2) 중복 많은 데이터(2,000개) 및 (3) 무작위 10,000개: 순서 위반 횟수**

| 알고리즘 | 중복 많은 데이터 | 무작위 10,000개 | 판정 |
|---|---:|---:|---|
| 선택 정렬 | 628 | 14 | **불안정** |
| 버블 정렬 | 0 | 0 | **안정** |
| 삽입 정렬 (`>`) | 0 | 0 | **안정** |
| 삽입 정렬 (`>=`) | 1,900 | 53 | **불안정** |

### 4.4 원인 설명
- **선택 정렬(불안정)**: 최솟값을 현재 위치 `i`와 **멀리 떨어진 위치와 교환**하기 때문입니다. 예시에서 `i=0`일 때 최솟값 `(125,300)`(인덱스 2)과 `(527,100)`(인덱스 0)을 교환하면, `(527,100)`이 `(527,200)`의 뒤로 넘어갑니다. 같은 키 데이터를 건너뛰어 이동시키므로 상대 순서가 깨집니다.
- **버블 정렬(안정)**: **인접한** 데이터끼리만, 그것도 `>`(엄격히 클 때)만 교환합니다. 키가 같으면 교환하지 않으므로 같은 키 데이터는 서로를 추월할 수 없습니다.
- **삽입 정렬(`>`: 안정 / `>=`: 불안정)**: 이동 조건이 `a[j] > cur`이면 키가 같은 데이터에서 이동을 멈추고 `cur`이 그 **뒤**에 삽입됩니다(원래 순서 유지). `a[j] >= cur`이면 키가 같은 데이터까지 한 칸 밀어내고 그 **앞**에 삽입되어, 나중에 들어온 데이터가 먼저 온 같은 키 데이터보다 앞서게 됩니다. 예시에서 `(527,200)`이 `(527,100)` 앞으로 갔습니다.
- **`>=`의 부수 효과**: 같은 키 데이터도 이동시키므로 **비교·이동이 조금 더 많습니다.** 무작위 평균 25,032,123 → 25,032,172(비교), 정렬된 입력에서 9,999 → 10,052(비교), 19,998 → 20,051(이동)로, 중복 키 쌍 수(약 53)만큼 증가합니다. 이는 정렬된 입력에서도 `>=`가 중복 키 때문에 불필요한 이동을 한다는 뜻입니다.

## 5. 입력 정렬 상태에 따른 성능 비교

### 5.1 입력 데이터 준비
- 무작위: 2번 실험의 결과 사용.
- 정렬/역순/부분 정렬은 **동일한 원본 데이터**(1회차 무작위 데이터)에서 파생. 사전 정렬(`qsort`)은 시험 입력 준비용이며 비교·이동 횟수에서 제외했습니다(정렬 알고리즘 구현에는 라이브러리 사용 없음).
- **부분 정렬 데이터 생성 방법**: 정렬된 데이터에서 **무작위 위치 두 개를 골라 교환하는 작업을 200번** 반복했습니다(최대 약 400개, 즉 전체의 약 4% 원소가 제자리에서 벗어남. 약 96%는 원래 위치 유지). 나머지 구간은 정렬 상태가 유지되므로 "대부분 정렬되어 있고 소수의 교란이 있는" 상태입니다.

### 5.2 측정 결과 (N = 10,000)

| **일부 정렬** | 선택 | 49,995,000 | 603 |

### 5.3 분석
- **선택 정렬**은 입력 상태에 **비교 횟수가 전혀 반응하지 않습니다**(항상 49,995,000). 정렬된 입력에서도 최솟값을 끝까지 탐색해야 하기 때문입니다. 반면 이동은 입력이 정렬에 가까울수록 줄어듭니다(0 ~ 약 1.5만). 역순의 이동 15,075는 약 5,000회 교환 × 3 + 중복 키로 인한 추가 교환입니다. 일부 정렬에서 603(약 200회 교환 × 3)은 교란한 200쌍이 거의 그대로 교환 횟수가 된 것입니다.
- **버블 정렬**은 이동이 곧 역전 수 × 3이어서 입력 상태에 가장 민감합니다. 정렬 0 → 일부 정렬 약 395만 → 무작위 약 7,507만 → **역순 약 1억 5천만**(`3 × n(n-1)/2`)으로, **역순에서 모든 알고리즘 중 최악**입니다. 조기 종료는 정렬된 입력에서만 극적으로 효과가 있고, 일부 정렬에서는 겨우 1.2% 줄었습니다. 이유는 뒤쪽에 있던 작은 값이 한 패스에 **한 칸씩만** 앞으로 이동하기 때문에, 교란이 조금만 있어도 거의 모든 패스를 돌아야 하기 때문입니다.
- **삽입 정렬**은 `비교 ≈ 이동 ≈ 역전 수`로 입력 상태를 가장 잘 활용합니다. 정렬된 입력에서 비교 `n-1 = 9,999`, 이동 `2(n-1) = 19,998`(O(n)), 일부 정렬에서는 약 133만 회로 무작위의 약 5%에 불과합니다. 역순에서는 모든 원소가 맨 앞까지 이동해 비교 49,995,000, 이동 약 5,001만 회(O(n²))로 최악이지만, 이때도 버블 정렬의 이동(1.5억)보다는 3분의 1 수준입니다.
- **종합**:
  - 이동 횟수가 중요(데이터가 크거나 복사 비용이 큰 경우)하면 → **선택 정렬**(이동이 O(n)으로 가장 적음)
  - 정렬에 가까운 입력이 많고 안정성이 필요하면 → **삽입 정렬 `>`**
  - 일반 버블 정렬은 모든 입력에서 비교가 많고 이동도 많아 실용성이 낮고, 조기 종료를 붙여야 정렬된 입력에서만 이점이 생깁니다.

## 6. 안정성 vs 성능 요약

| 알고리즘 | 안정성 | 비교 횟수 입력 의존성 | 이동 횟수 입력 의존성 |
|---|---|---|---|
| 선택 정렬 | 불안정 | 없음(항상 n(n-1)/2) | 작음(최대 약 3n) |
| 버블 정렬 | 안정 | 없음 (조기 종료 시 약간) | 매우 큼(3 × 역전 수) |
| 삽입 정렬 `>` | 안정 | 큼(O(n) ~ O(n²)) | 큼(역전 수 + 2(n-1)) |
| 삽입 정렬 `>=` | 불안정 | `>`와 거의 동일(중복 키만큼 증가) | `>`와 거의 동일 |

## 7. 인공지능(AI) 활용 내용
- 부분 정렬 데이터 생성 방식 조사 및 설계에 AI(Claude)를 활용했습니다. 후보로 ① 정렬 데이터에서 일부 원소를 무작위로 교환, ② 일정 구간만 섞기, ③ 소수의 무작위 교란 추가를 검토했고, **재현이 쉽고 교란 정도를 수치(교환 200회)로 정의할 수 있는 ①번**을 선택했습니다.
- 안정성 검증을 위해 원래 입력 순서(`id`)를 별도로 저장하는 방식과, 중복 키가 많은 별도 시험 데이터를 만드는 방법도 AI의 조언에 따라 적용했습니다.
- 모든 수치는 위 프로그램을 직접 실행하여 얻은 값이며, 정렬 결과의 정확성(오름차순 + 원본 데이터 보존)을 코드로 검증했습니다.

## 8. 한계 및 참고
- 부분 정렬은 "200회 무작위 교환" 한 가지 방식만 사용했습니다. 교란 정도(교환 횟수)를 바꾸면 버블(조기 종료)·삽입의 비교 횟수가 달라집니다.
- 부분 정렬·역순·정렬 케이스는 1회차 원본 한 개에서 만든 단일 측정값이라, 무작위 케이스처럼 평균이 아닙니다.
- 선택 정렬은 `m != i`일 때만 교환하도록 구현했으므로, 매번 무조건 교환하는 구현과는 이동 횟수가 다를 수 있습니다.
