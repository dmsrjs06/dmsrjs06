# 과제-05: 순차 탐색과 이진 탐색 트리 탐색의 비교

## 1. 프로그램 개요

`search_compare.c`는 0~1000 사이의 서로 다른 정수 100개를 발생 순서 그대로
배열에 저장하고, 같은 순서로 이진 탐색 트리(BST, 포인터 기반 연결 자료구조)에
삽입한다. 이어서 0~1000 사이의 정수 50개를 탐색 대상으로 생성하여, 배열에서는
순차 탐색을, BST에서는 BST 탐색을 수행하고 각각의 숫자 비교 횟수를 측정한다.
BST를 구성하는 과정에서 발생한 비교 횟수도 별도로 측정한다.

- 비교 횟수 정의: 순차 탐색은 배열 원소 하나와 비교할 때마다 1회, BST 탐색/삽입은
  노드 하나를 방문하여 대소(또는 일치) 비교를 할 때마다 1회로 계산한다.
- 컴파일: `gcc -Wall -o search_compare search_compare.c`
- 실행: `./search_compare` (실행할 때마다 `srand(time(NULL))`로 난수를 새로 생성하므로
  매번 다른 데이터로 시험된다.)

아래 분석은 실제로 한 번 실행한 결과(`run_output.txt`)를 기준으로 작성하였다.
실행할 때마다 생성되는 난수가 다르므로 수치는 매번 달라질 수 있지만, 아래에서
설명하는 경향성(순차 탐색과 BST 탐색의 비교 횟수 차이, 생성 비용을 고려한
손익분기점, 트리 구조의 영향)은 거의 모든 실행에서 공통적으로 관찰된다.

## 2. 측정 결과

### 2.1 순차 탐색 (Sequential Search)

| 항목 | 값 |
|---|---|
| 총 비교 횟수 | 4,817 |
| 평균 비교 횟수 | 96.34 |

### 2.2 BST 탐색 (BST Search)

| 항목 | 값 |
|---|---|
| 총 비교 횟수 | 476 |
| 평균 비교 횟수 | 9.52 |

### 2.3 BST 생성 비용

| 항목 | 값 |
|---|---|
| 100개 삽입 시 총 비교 횟수 | 688 |
| 삽입 1회당 평균 비교 횟수 | 6.88 |

### 2.4 BST 구조

| 항목 | 값 |
|---|---|
| 트리 높이(루트 깊이 = 0) | 13 |
| 평균 노드 깊이 | 6.88 |
| 노드 100개를 완전히 균형 잡히게 구성했을 때의 이상적 높이 | 약 7 (log2(100) ≈ 6.64) |

(50개 탐색 대상 중 found는 6개, not found는 44개였다. 전체 수치는

## 3. 분석

### 3.1 두 탐색 방법의 성능 차이

같은 50개의 탐색 대상에 대해 순차 탐색은 평균 96.34회, BST 탐색은 평균 9.52회의
비교가 필요했다. 약 10배의 차이이다. 이는 두 탐색 방법의 시간 복잡도 차이에서
비롯된다.

- 순차 탐색은 최악의 경우(값이 없거나 배열 끝에 있는 경우) 배열 전체를
  확인해야 하므로 O(n)이다. 실제로 탐색 대상 50개 중 44개가 데이터에 존재하지
  않아(not found) 매번 배열 전체(100회)를 비교했고, 이것이 평균 비교 횟수를
  거의 100에 가깝게 끌어올렸다.
- BST 탐색은 각 단계마다 왼쪽/오른쪽 절반을 배제하면서 내려가므로, 트리가
  균형에 가까울수록 O(log n)에 근접한다. 100개의 노드라면 이상적으로는
  약 7번의 비교로 탐색이 끝나야 하는데, 실제 평균은 9.52회로 이상적인
  경우보다 조금 많지만 여전히 순차 탐색과는 자릿수 자체가 다르다.

즉, 데이터 개수가 늘어날수록 두 방법의 격차는 더 벌어진다. 순차 탐색은 n에
비례해서 느려지지만 BST 탐색은 log n에 비례해서만 느려지기 때문이다.

### 3.2 BST 생성 비용을 고려했을 때의 성능 차이

BST는 공짜로 만들어지지 않는다. 100개의 값을 삽입하는 데만 688회의 비교가
필요했다. 이는 평균적인 BST 탐색 1회 비용(9.52회)의 약 72배에 해당하는 비용을
트리를 만드는 데 먼저 지불한 셈이다.

따라서 BST 생성 비용까지 포함하면,

- 순차 탐색 50회의 총 비용: 4,817
- BST 탐색 50회 + BST 생성 비용의 총 비용: 476 + 688 = 1,164

이 경우에도 BST 쪽이 약 4.1배 더 적은 비교로 끝난다. 하지만 탐색 횟수가
더 적었다면 결과가 달라질 수 있다. 생성 비용(688)을 회수하려면 "순차 탐색
1회당 비용 − BST 탐색 1회당 비용"만큼의 차이가 쌓여야 하므로, 손익분기점은

```
손익분기 탐색 횟수 ≈ 생성 비용 / (순차 탐색 평균 − BST 탐색 평균)
                  = 688 / (96.34 − 9.52)
                  ≈ 7.9회
```

로 계산된다(프로그램의 "=== 6. Combined cost comparison ===" 항목에서 동일하게
출력된다). 즉 탐색을 8회 이상 수행할 예정이라면 BST를 만드는 비용을 포함하더라도
BST가 더 유리하고, 탐색을 그보다 훨씬 적게(예: 1~2회만) 할 것이라면 매번 트리를
새로 만드는 것보다 차라리 순차 탐색이 더 쌀 수도 있다. 다시 말해 BST의 이점은
"한 번 만들어 놓고 여러 번 탐색할 때" 극대화된다.

### 3.3 트리 구조가 탐색 성능에 미치는 영향

이번 실행에서 실제 트리의 높이는 13이었고, 평균 노드 깊이는 6.88이었다.
100개의 노드를 완전 균형 이진트리로 만들었을 때의 이상적인 높이(약 7, log2(100))와
비교하면 실제 높이가 거의 2배 가까이 된다. 이는 노드들이 "무작위 순서"로
삽입되긴 했지만 삽입 순서에 따라 한쪽으로 치우친 경로가 일부 생겼기 때문이다.
BST 탐색의 비교 횟수는 결국 탐색 경로의 길이(=그 노드의 깊이)이므로, 평균
노드 깊이(6.88)가 실제 측정된 BST 탐색 평균 비교 횟수(9.52)와 비슷한 수준으로
나타난 것도 이 때문이다(참고로 found 탐색은 해당 노드까지의 깊이+1만큼,
not found 탐색은 가장 가까운 빈 자리까지의 깊이만큼 비교가 필요하므로 두
수치가 정확히 같지는 않다).

일반적으로 BST의 탐색 성능은 트리의 모양(높이)에 의해 결정되며, 트리의 모양은
전적으로 "삽입 순서"에 의해 결정된다.

- 무작위 순서로 삽입하면(이번 실험처럼) 평균적으로 O(log n)에 가까운, 적당히
  균형 잡힌 트리가 만들어진다.
- 반대로 이미 정렬된 순서(오름차순 또는 내림차순)로 삽입하면 모든 노드가
  한쪽 자식만 가지는 연결 리스트 형태가 되어 높이가 n-1까지 치솟는다. 이
  경우 BST 탐색은 순차 탐색과 똑같이 O(n)이 되어 BST를 사용하는 이점이
  완전히 사라진다.
- 즉 같은 100개의 값이라도 "어떤 순서로 넣었는가"에 따라 탐색 성능이
  크게 달라질 수 있으며, 이번 실험에서 높이가 이상적인 값보다 컸던 것도
  무작위 순서 안에서도 운 나쁘게 한쪽으로 긴 경로가 몇 개 섞였기 때문이다.
  (이 문제를 구조적으로 해결하려면 AVL 트리나 레드-블랙 트리처럼 삽입 시
  스스로 균형을 맞추는 자료구조를 사용해야 하며, 그 경우 높이가 항상
  O(log n)으로 보장된다.)

## 4. 결론

- 탐색 1회만 놓고 보면 BST 탐색이 순차 탐색보다 약 10배 적은 비교로 끝난다.
- BST를 만드는 데 드는 비용(688회)까지 더하더라도, 탐색을 약 8회 이상
  수행한다면 BST 쪽이 여전히 더 적은 총 비교 횟수로 끝난다. 즉 데이터를
  "한 번 구축해 놓고 여러 번 반복해서 탐색"하는 상황일수록 BST가 유리하다.
- 다만 BST의 이러한 이점은 트리가 어느 정도 균형 잡혀 있을 때만 성립한다.
  삽입 순서가 정렬되어 있는 등 특수한 경우에는 트리가 한쪽으로 치우쳐
  순차 탐색과 다를 바 없는 성능을 보일 수 있다.
