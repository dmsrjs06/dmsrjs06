# 과제 08: 최소 비용 신장 트리(MST) 알고리즘 비교

## 1. 실행 방법

```
gcc -O2 -o mst mst.c
./mst 2026        # 인자는 난수 seed (생략하면 현재 시각)
```

- 정점 50개, 가중치 1~100의 무방향 단순 그래프 (self-loop, 중복 간선 없음)
- 연결성 보장: 임의의 신장 트리(49개 간선)를 먼저 만든 뒤 나머지 간선을 중복 없이 추가하고, 마지막에 연결 여부를 다시 검사
- 희소 그래프(E=100)와 밀집 그래프(E=600)는 각각 **하나씩만** 생성하고, Kruskal과 Prim이 같은 그래프를 사용
- 실행시간: MST 계산만 측정(그래프 생성·출력 제외). 값이 너무 작아 **20,000회 반복 실행 후 1회 평균**을 사용했고 4가지 경우 모두 같은 방법과 단위(ms)를 사용
- 메모리: `sizeof` 기반 직접 계산 (그래프 표현 + 주요 보조 자료구조, 난수·출력용 메모리 제외)

## 2. 실행 결과 (seed = 2026)

| Case | 그래프 | 표현 + 알고리즘 | MST 간선 수 | MST 비용 | 메모리 (Byte) | 실행시간 (ms) |
|---|---|---|---|---|---|---|
| 1 | Sparse (E=100) | 인접 리스트 + Kruskal | 49 | 1668 | 5,788 | 0.006392 |
| 2 | Dense (E=600) | 인접 리스트 + Kruskal | 49 | 289 | 27,788 | 0.056337 |
| 3 | Sparse (E=100) | 인접 행렬 + Prim | 49 | 1668 | 11,038 | 0.004178 |
| 4 | Dense (E=600) | 인접 행렬 + Prim | 49 | 289 | 11,038 | 0.005935 |

- 같은 그래프에서 Kruskal과 Prim의 MST 비용이 일치함 (Sparse 1668, Dense 289). seed 1~5로도 반복 실행해 모두 일치하는 것을 확인했다.
- 실행시간은 실행 환경에 따라 달라지므로 숫자 자체보다 **경우 간의 비율**이 의미 있다.

### 메모리 계산 내역 (`sizeof(Node)=16`, `sizeof(Edge)=12`, `sizeof(int)=4`, 포인터 8B 기준)

| 항목 | Kruskal (E=100) | Kruskal (E=600) | Prim (공통) |
|---|---|---|---|
| 그래프 표현 | head 400 + 노드 2E×16 = 3,600 | 400 + 19,200 = 19,600 | 행렬 50×50×4 = 10,000 |
| 간선 배열 | E×12 = 1,200 | 7,200 | - |
| Union-Find (parent, rank) | 400 | 400 | - |
| key[], parent[], visited[] | - | - | 400 + 50 = 450 |
| MST 결과 (49×12) | 588 | 588 | 588 |
| **합계** | **5,788** | **27,788** | **11,038** |

## 3. 분석

### 3.1 희소 그래프 vs 밀집 그래프

- **Kruskal**: 희소 → 밀집으로 갈 때 실행시간이 약 0.0064 ms → 0.0563 ms로 **약 8.8배** 증가했다. 간선이 6배(100→600) 늘었고, 정렬 비용이 O(E log E)라서 간선 수보다 조금 더 크게 늘어난다.
- **Prim**: 0.0042 ms → 0.0059 ms로 **약 1.4배**만 증가했다. 이 구현은 간선 수와 관계없이 O(V²) 작업(최소 정점 탐색 + 행렬 한 행 훑기)을 하기 때문이다. 증가분은 `m[u][v] != 0` 인 경우의 key 갱신 횟수 정도다.

### 3.2 인접 리스트와 인접 행렬의 메모리

- 인접 행렬은 간선 수와 무관하게 V² 크기로 **고정**이다(10,000 B). 그래서 Case 3과 Case 4의 메모리가 11,038 B로 동일하다.
- 인접 리스트는 무방향 그래프에서 간선당 노드 2개(2E)를 쓰므로 간선 수에 **비례**한다. 희소 그래프(E=100)에서는 리스트 표현이 약 3.6KB로 행렬(10KB)의 1/3 수준이라 유리하지만, 밀집 그래프(E=600)에서는 약 19.6KB로 행렬의 2배 가까이 되어 오히려 불리했다.
- 이번 실험에서 Kruskal 쪽은 정렬용 간선 배열(E×12 B)이 추가로 필요해 간선이 많을수록 메모리 부담이 더 커졌다. 전체 합계 기준으로 희소에서는 Kruskal(5,788) < Prim(11,038), 밀집에서는 Kruskal(27,788) > Prim(11,038)로 **역전**됐다.
- 손익분기점은 대략 2E×16 + E×12 ≈ 10,000 → E가 약 230개 부근이다(이 구현의 자료형 크기 기준).
- 이번 경우 노드를 `malloc`으로 개별 할당했으므로 실제 힙 사용량은 할당자 헤더 때문에 위 계산값보다 더 클 수 있다.

### 3.3 Kruskal과 Prim의 실행 특성

| 구분 | Kruskal (리스트) | Prim (행렬) |
|---|---|---|
| 핵심 연산 | 간선 정렬 + Union-Find | 정점 중심, 최소 key 정점 선택 |
| 시간 복잡도 | O(E log E) | O(V²) |
| 간선 수 의존성 | 큼 | 거의 없음 |
| 이번 실험에서 유리한 경우 | 희소 그래프(이론적으로) | 밀집 그래프 |

- 이론상 희소 그래프에서는 Kruskal이 유리할 것으로 기대되지만, 이번 실험(V=50)에서는 Case 3(Prim, 0.0042 ms)이 Case 1(Kruskal, 0.0064 ms)보다 빨랐다. V=50으로 매우 작아 O(V²)=2,500회 연산이 작고, Kruskal은 리스트에서 간선을 꺼내 **malloc/qsort/함수 포인터 호출** 같은 고정 비용이 있기 때문이다. 또한 Prim은 연속된 배열 접근이라 캐시 효율이 좋은 반면, 연결 리스트는 포인터를 따라가야 한다.
- 밀집 그래프에서는 Prim이 Kruskal보다 약 **9.5배** 빨랐다(0.0059 vs 0.0563 ms). 간선 600개를 정렬해야 하는 Kruskal의 부담이 크기 때문이다.

### 3.4 그래프 밀도의 영향 요약

- 밀도가 높아질수록 **간선 수에 의존하는 방법**(리스트 메모리, Kruskal 시간)은 비용이 크게 늘고, **정점 수에만 의존하는 방법**(행렬 메모리, Prim 시간)은 거의 변하지 않았다.
- 따라서 희소 그래프에서는 메모리 측면에서 인접 리스트 + Kruskal, 밀집 그래프에서는 인접 행렬 + Prim이 효율적이라는 이론적 선택 기준이 실험에서도 확인되었다. 다만 실행시간은 V가 작은 이번 조건에서는 상수 비용의 영향으로 희소 그래프에서도 Prim이 약간 빨랐다. 정점이 훨씬 많아지면(예: V=10⁴ 이상) O(V²)의 부담이 커져 희소 그래프에서 Kruskal이 앞설 것으로 예상된다(추가 실험하지 않은 추정).

## 4. 한계

- 단일 seed(2026) 결과를 표로 정리했다. 다른 seed에서도 MST 비용 일치와 간선 수 49는 확인했지만 실행시간 비율은 환경과 그래프에 따라 달라질 수 있다.
- 메모리는 프로파일링이 아니라 `sizeof` 계산값이다.
